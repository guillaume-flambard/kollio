## Context

The real-decision-loop validation establishes whether a two-person loop reaches outcome and voluntary return. This complementary change examines why the workflow is started, how it supports coordination and disagreement, and whether participants perceive durable value and trust. It is an evidence protocol, not a commitment to build new surfaces.

## Goals / Non-Goals

**Goals:**

- Make the six identified adoption risks falsifiable during the pilot.
- Prevent feedback from becoming an undifferentiated feature backlog.
- Preserve confidentiality by keeping decision content outside the evidence record.

**Non-Goals:**

- Add telemetry, notifications, ranking, recommendation, export, or integrations.
- Quantify broad market demand or prove PMF from one pilot.
- Resolve a disagreement on behalf of a team.

## Decisions

### Observe workflow moments rather than instrument every interaction

The evidence record will capture the start trigger, next-action clarity, disagreement outcome, debriefed value, memory expectation, and portability trust. This is sufficient for a small qualitative pilot and avoids collecting behavior that does not answer a decision risk.

### Require a bounded answer for each angle

Each angle ends with one of: supported, unsupported, unobserved, or inconclusive. This prevents a missing event, such as no disagreement, from being treated as success or failure.

### Gate new features on recurrence or milestone impact

A new product change is justified only by a recurring friction or one that blocks completing the loop. This protects the current focused V1 from expanding around single preferences.

## Risks / Trade-offs

- [One pilot may not exercise every angle] → Mark that angle unobserved and preserve it for the next pilot rather than inventing a conclusion.
- [A facilitated session can distort the trigger and coordination evidence] → Record facilitation at each observed moment and separate it from participant-initiated behavior.
- [Debrief recall can be biased] → Record concrete examples and evidence references before asking for interpretations.
- [Feedback asks for a feature outside V1] → Keep the request as a deferred decision unless recurrence or a blocking impact is shown.

## Migration Plan

1. Add the observation table to the pilot acceptance record before the session.
2. Capture evidence references at each relevant moment without copying content.
3. Run the debrief after the loop or its stopping point.
4. Classify each angle and create follow-up changes only where the decision rule is met.
