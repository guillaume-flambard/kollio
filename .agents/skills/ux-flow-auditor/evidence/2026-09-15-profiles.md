## Findings

1. **Locale parameter mismatch breaks EN interpolation.** The catalogue keys
   `ideas.profile.onIdea` (fr `"sur {idea}"`, en `"on {initiative}"`) and
   `ideas.profile.roleIn` (fr `"dans {idea}"`, en `"in {initiative}"`) use a
   different placeholder name in EN than the call sites pass.
   `people/[userId].vue:60` calls
   `t('ideas.profile.roleIn', { idea: membership.idea_title })` and line 72
   calls `t('ideas.profile.onIdea', { idea: act.idea_title })`, so the English
   profile renders the literal `{initiative}` instead of the initiative title in
   both the teams and acts sections. Neither PROFILE-01 nor PROFILE-02 asserts
   those two lines, so the defect passes green.
2. **Date not localised.** `people/[userId].vue:73` renders
   `new Date(act.created_at).toLocaleDateString()` with no locale argument, so
   the contribution date follows the browser locale rather than the active
   `fr`/`en` locale. Compare `ideas/[ideaId].vue:30` and `index.vue:62`, which
   correctly build `Intl` formatters from `locale.value`.
3. **Error state not tokenised.** `.profile-error` (`people/[userId].vue:96`)
   only sets `display: grid`; neither the 404 branch nor the load-error branch
   applies `--ui-error`.

## Verdict

PROFILE-01 and PROFILE-02 AUDITED for fr and en. Finding 1 is a real en-only
rendering defect that the current scenarios do not cover.
